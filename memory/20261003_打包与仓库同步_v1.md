## 二、这次修掉的三个打包问题（都不是小问题）

### 1. 脚本「明明打好了包却报失败」
Chrome 是 **GUI 程序**，PowerShell 执行 `& chrome.exe ...` 时**不会等它跑完**就往下走；
而打包本身也是异步的。脚本却紧接着就去检查 `.crx` 是否存在 —— 那时 Chrome 还没写完，
于是报「未生成 .crx」，**而实际上包已经生成好了**。

修复：轮询等 `.crx` 出现、并等它大小连续两次一致（确认写完），最多等 60 秒。

### 2. 直接把项目目录打包，会把 `.git` 和本机记录塞进用户的 `.crx`
`chrome --pack-extension=<项目目录>` 会把目录里**所有东西**打包，包括 `.git`（完整提交历史）、
`tests/`、`memory/`（工作记录）、`drafts/`、`trash/`，甚至里面若有的私钥。

修复：先复制一份「只含运行必需文件」的快照（排除 `.git`、`.agents`、`tests`、`memory`、
`drafts`、`trash`、`dist`、`node_modules`、打包脚本、私钥/产物/日志），对快照打包，
完事删掉快照。这样用户拿到的 `.crx` 里只有插件本身。

### 3. `pack-crx.ps1` 没有 UTF-8 BOM，Windows PowerShell 5.1 会把它读成乱码
PowerShell 5.1 读**没有 BOM 的 `.ps1`** 时按系统代码页（GBK）解码：中文提示变成乱码，
这次甚至直接破坏语法解析（`Unexpected token '绉侀挜鏂囦欢:'`）。
`pack-crx.bat` 调的是 `powershell`（5.1），所以用户自己跑也会中招。

修复：给 `.ps1` 加 UTF-8 BOM。**注意**：以后改这个文件要用能保留 BOM 的方式写
（本次用 `[System.IO.File]::ReadAllText/WriteAllText` + `UTF8Encoding($true)`）。

> 另一个同类坑：**不要用 PowerShell 做文本替换**改源码（PS 5.1 会按 GBK 读 UTF-8 再按
> UTF-8 写回，整个文件中文变乱码，而 `node --check` 照样通过）。详见
> `memory/20261003_插件内手势对照表_v1.md`。

## 五、你接下来要做的：把 `.crx` 发到 Release

`.crx` 只在本地（`dist\`，故意不上传仓库 —— 仓库里放二进制不合适，Release 才是给它待的地方）。
发 Release 的步骤（3 步）：

1. 打开 <https://github.com/yidiqingyu/gesture-video-control/releases/new?tag=v1.3.0>
   （标签 `v1.3.0` 已经推上去了，直接选它即可）；
2. 在「Attach binaries」区域把 `D:\gesture-video-control\dist\gesture-video-control.crx` 拖进去；
3. 填个标题（例如 `v1.3.0 —— 手势判定重做 + 断线自愈 + 手势表 + 观看类手势闸门`），
   点 **Publish release**。

> 本机没有 `gh` 命令、我也没有你的 GitHub token，所以这一步没法替你点。
> 想让我以后能直接发 Release，可以装 [GitHub CLI](https://cli.github.com/) 并 `gh auth login`。

## 六、备份提醒

`dist\gesture-video-control.pem` 是**扩展身份**：以后更新 `.crx` 必须用它（`-Key` 参数），
否则会变成一个新的扩展 ID，老用户装上会看到"两个扩展"。
建议把它复制到你自己的私密备份里（**不要**放仓库、不要放公开网盘目录）：

```powershell
powershell -ExecutionPolicy Bypass -File .\pack-crx.ps1 -Key .\dist\gesture-video-control.pem
```
