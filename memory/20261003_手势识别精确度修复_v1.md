# 手势识别精确度修复（判定算法 v2）

- 日期：2026-10-03
- 版本：插件 1.0.0 → 1.1.0
- 起因：用户反馈「手势识别不够精确」，五种症状全中：认错手势 / 音量切集方向乱跳 / 误触发 / 迟钝 / 手歪一点就不认

## 一、结论（根因）

老版判定逻辑有两个**结构性错误**，不是阈值没调好：

1. **用手指「距离比值」判断伸没伸直，方向是错的**
   `gesture.js` 旧版算 `指尖到指根距离 ÷ PIP 到指根距离`，大于 1.25 就算伸直。
   但手掌正对镜头蜷手指时，手指是**朝镜头方向**弯的，PIP 在画面上几乎和指根重合，
   分母趋近 0 → 比值暴涨。用合成手实测：**蜷曲的中指该比值为 7.6**（门槛只要 1.25），
   蜷着的手指被稳稳判成「伸直」。git 历史里那一长串
   `fix: 放宽/收紧 XX 判定，避免误判成 YY` 全是在给这个坏特征打补丁。

2. **方向阈值只有 4~5 像素**
   `食指向上/下`、`小拇指向上/下` 用的是 `y 差 > 0.008`（640×480 下约 4 像素）。
   手指稍微偏一点水平，上下就来回翻转 —— 直接表现就是**音量加/减乱跳、上一集/下一集乱跳**。

另外四个次要问题：

3. 永远取 `hands[0]`：画面出现第二只手（或误检）时，主手势在两只手之间跳。
4. 完全没有时间维度的平滑：只数「连续 3 帧同名」，抖动一帧就清零重来。
5. 归一化坐标没做宽高比校正（x 按宽、y 按高，640×480 下横向失真 25%）。
6. 检测置信度 0.4 低于官方默认 0.5，容易把身体/背景误检成手；
   OK 捏合半径 = 手掌长 × 0.35（约 3cm）偏松，且完全不检查小指。

**顺手发现的独立 bug：`float.js` 第 887 行有一个多余的 `}`，整个文件语法错误、根本加载不了**
（旧版独立悬浮窗早就打不开了，只是弹窗已经不入口它，没人发现）。

## 二、改了什么

### `gesture.js`（判定核心，重写）
- 手指伸展度改成**关节夹角**为主（伸直≈180°、蜷曲≈50°），距离比只占 25% 权重；
  投影不会说谎，蜷曲的中指现在得 0 分。
- 图像坐标先乘宽高比换算成等尺度；再和 MediaPipe **世界坐标（米制 3D）**各算一遍取平均。
- 拇指单独处理：以**外展距离**为主（拇指「收」是内收动作，关节反而是直的，夹角分不出来）。
- 方向判定改成**竖直圆锥**：与竖直方向夹角 > 55°（拇指 76°）判为「方向不明」→ 不动作。
  宁可不动，也不猜错方向。
- 容易混的手势之间留**死区**：如「数字 4（拇指收）」与「手掌张开（拇指伸）」之间不猜。
- 点赞要求拇指**朝上**（倒过来比不再触发）。
- 新增 `pickPrimaryHand()`：按「居中 + 离镜头近 + 沿用上一帧 + 左右手一致」挑主手。
- 新增 `createSmoother()` / `createPoseTracker()`：最近 5 帧多数投票 + 稳定 2 帧确认，
  并把「挑主手 → 判定 → 平滑 → 稳定确认」串成一条流水线，两个引擎共用。

### `offscreen.js` / `float.js`（两个识别引擎）
- 改用 `createPoseTracker()`，删掉各自抄一份的主手/平滑/稳定帧逻辑（改一处漏一处的温床）。
- 判定时传入画面宽高比与世界坐标；双手手势（点赞/交叉）也走同一套参数。
- 检测置信度 0.4 → 0.45 / 0.45 / 0.5。
- 稳定帧从固定 3 帧改成 2 帧（平滑器已在做时间过滤），总体响应约 0.17 秒，比旧版更抗抖也更快。
- `float.js` 删掉第 887 行多余的 `}`（语法错误）。

### 新增 `tests/`（离线自测，不参与打包）
- `hand-model.mjs`：用**正运动学合成一只手**（21 个关键点），可按姿势 / 手歪 / 宽高比 /
  远近 / 左右手 / 抖动噪声自由生成，还能模拟 MediaPipe 的透视投影。
- `gesture-selftest.mjs`：228 项判定断言。
- `engine-sim.mjs`：12 项时序断言（抗抖动 / 跟手速度 / 主手不跳 / 漏检容错）。
- `integration-check.mjs`：38 项静态体检（manifest、HTML 引用、引擎与 gesture.js 的接口一致性）。
- `run-all.mjs`：一条命令跑完全部。
- `gesture-inspect.mjs`：打印每个手势的中间量，调阈值时看它。
