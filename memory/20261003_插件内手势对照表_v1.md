# 插件内手势对照表（点开就能查）+ 两个自查事故

- 日期：2026-10-03
- 版本：插件 1.2.0（功能增加，未升版本号；对外发布可升 1.3.0）
- 需求：把现有的手势表格做进插件里，用户可以点开查看手势列表

## 一、做了什么

以前手势表只存在于 README 里，用户得跳出浏览器翻文档。现在插件内两处可查：

| 位置 | 入口 | 说明 |
| --- | --- | --- |
| 弹窗 | 底部 **📖 手势对照表** 按钮 | 点击展开/收起；展开状态记在 `storage.local.gestureHelpOpen`，下次打开还是展开的；列表区最高 300px，超出可滚动 |
| 页面内悬浮面板 | 标题栏 **📖** 按钮 | 同一个表格显示在面板里（面板 body 本身可滚动），按钮按下时高亮 |

内容分 5 组（播放控制 / 音量 / 切视频 / 模式与锁定 / B 站专属）+ 5 条「识别小贴士」
（手指要竖直、稳定约 0.17 秒才触发、数字 4 与 5 的区别、多只手时锁定主手等）。

## 二、设计要点：一份数据，两处显示

新增 `gesture-catalog.js`，把**数据 + HTML 渲染 + 配套样式**放在一个文件里：

- `GestureCatalog.groups` / `.tips` —— 手势数据（唯一数据源）
- `GestureCatalog.toHTML()` —— 渲染成 HTML 字符串（内部做了转义）
- `GestureCatalog.css()` —— 配套样式（弹窗塞进 `<style>`，悬浮面板塞进 Shadow DOM）

弹窗（`popup.js`）和悬浮面板（`content.js`）都从它取，**改一处两边都对**。

⚠️ 代价：`content.js` 现在依赖 `gesture-catalog.js` 先加载。所有注入 `content.js` 的地方
（manifest 的 `content_scripts` + 5 处 `scripting.executeScript`）都必须连带注入它 ——
这一点由 `5b-注入清单` 检查自动盯着（漏一处就报错，已用"故意改坏再跑"验证过能抓住）。

## 三、⚠️ 这次任务里踩的两个坑（都要记住）

### 坑 1：用 PowerShell 做文本替换，把 4 个文件的中文全变成乱码

改注入清单时图快，用了：

```powershell
$t = Get-Content $f -Raw; $t -replace "files: \['content\.js'\]", "..." | Set-Content ...
```

**Windows PowerShell 5.1 读 UTF-8 源码时按系统代码页（GBK）解码，再按 UTF-8 写回**，
`background.js` / `float.js` / `popup.js` / `manifest.json` 的中文全部变成乱码
（`后台 Service Worker` → `鍚庡彴 Service Worker`）。要命的是：

- **`node --check` 照样通过**（乱码也是合法字符串），看不出任何异常；
- 只有用支持 UTF-8 的方式读文件才暴露。

**发现方式**：`git diff --numstat` —— 本该只改 1 行的文件显示 182/182 行，行数不对就是信号。

**处理**：`cmd /c "git show HEAD:<文件> > 临时文件"`（cmd 重定向是字节级、不会重新编码）
从 git 恢复，再用编辑工具重做改动。

**规矩**：改这些源码一律用编辑器/编辑工具，**不要用 PowerShell 做文本替换**。
`7-编码` 检查会拦住这种事故（26 个文件全查）。

### 坑 2：更严重 —— 四个测试文件的断言参数顺序写反了，大部分检查是"永远通过"

写测试时 `record()` 的调用写成了 `record(分组, 说明, 条件)`，但定义是
`record(group, ok, label, extra)` —— 于是**"说明字符串"落到了 `ok` 参数位置**，
永远为真，这些检查全部变成装饰品（`manifest.json` 解析失败都会被报成通过）。

- 只有走 `check(分组, 说明, 实际, 期望)` 包装函数的检查是真的（那个包装内部顺序是对的），
  所以之前"旧代码 161 项失败"这类结论仍然成立，但 `4-抖动容忍`、`5b-注入清单`、
  `7-编码`、`8-手势表` 这些组一直是假绿。
- **怎么暴露的**：`7-编码` 本应报出"测试文件自己含有乱码标记字"，却显示通过 ——
  顺着这条线查出参数顺序问题。

**修复**：四个测试文件的 `record` 签名统一改成 `(分组, 说明, 条件, 附加信息)`，
并各自加一条「0-断言器自检」——**故意喂一个假条件，确认它真会被记成失败**，
否则整个文件的检查都是白做。这条自检以后会一直盯着这个坑。

**顺带验证测试有效性**：故意把 `manifest.json` 的 `content_scripts.js` 改回 `["content.js"]`，
跑检查确认 `5b-注入清单` 真的报错（9/10 ❌），然后还原 —— 证明检查有牙齿。
