# 界面改版：设计令牌 + 双主题 + 矢量图标（v1.4.0 前置）

日期：2026-10-04
范围：popup / float / content(页面内面板) / grant 四套界面 + 新增 theme.css、ui-icons.js

## 1. 为什么要改

原来看起来是"三家人"：

| 界面 | 改前 |
| --- | --- |
| 工具栏弹窗 popup | 深色板岩蓝 `#101826`，emoji 当图标，状态行是整块色块 |
| 独立悬浮窗 float | 深色 `#0d1522`，和弹窗像但不完全一致 |
| 页面内面板 content.js | **白底 + 蓝色渐变标题栏**，和上面两个完全不是一套 |
| 授权页 grant | 又一个自己的配色 `#101826` |

三处各写各的色值 —— 改一个颜色要改四个地方，还容易改歪。用户要求：有质感 + 一点科技感。

## 2. 做了什么

### 2.1 一套设计令牌（theme.css）

新建 `theme.css`，是**全项目唯一的色值 / 圆角 / 阴影 / 动效来源**。三处怎么拿到它：

- 弹窗 / 悬浮窗 / 授权页 → `<link rel="stylesheet" href="theme.css">`
- 页面内面板（Shadow DOM）→ manifest 的 `content_scripts.css` 注入到页面 `:root`。
  自定义属性会从宿主元素继承进 Shadow DOM，所以面板里的 `var(--gvc-*)` 一样生效。
  **theme.css 里只有 `:root { --gvc-* }`，不写任何元素选择器** —— 否则会污染视频网站自己的样式。
- 补注入（`chrome.scripting.executeScript`）的那几条路径，额外用 `insertCSS` 把 theme.css 插进去，
  否则那些标签页里没有令牌，面板会变成没有样式的透明框。

### 2.2 双主题（跟随系统）

深色为默认，`@media (prefers-color-scheme: light)` 覆盖一整套浅色值。
摄像头画面（`--gvc-stage`）两种主题下都保持深色：视频画面本身发光，浅底反而刺眼。

`prefers-reduced-motion` 的降级也放在 theme.css 一处：动效时长归零 + 循环动画设为 `none`
（令牌 `--gvc-pulse-anim` / `--gvc-scan-anim`，用它的地方自动跟着关）。

### 2.3 内联 SVG 图标（ui-icons.js）

新增 `ui-icons.js`：一套统一线宽 1.6 的描边图标（手 / 眼睛 / 最小化 / 关闭 / 书 / 相机 / 面板 / 提示），
颜色用 `currentColor`，深浅主题自动适配。HTML 里写 `<span data-icon="camera" data-size="15"></span>`，
脚本里调一次 `UIIcons.mount(root)` 就替换成 SVG。

加载顺序（三处都要）：`gesture-catalog.js` → `ui-icons.js` → `content.js` / 各自的控制器。

### 2.4 视觉手法（参考 Linear / Vercel / Raycast / Apple）

- 三层递进底色：`--gvc-bg` → `--gvc-bg-soft` → `--gvc-surface`，每层 1px 描边 + 顶部 1px 高光
- 全局只有一个强调色（电光蓝 `#4F8BFF`，浅色下 `#2F6BFF`）；绿/黄/红只用在小圆点和文字上，不再铺色块
- 状态行改成「彩色小圆点 + 文字」胶囊（纯 CSS `::before`，不用改 JS）
- 开关统一 44×24 轨道 + 18px 滑块，开启态强调色渐变 + 微光；键盘 `focus-visible` 有焦点环
- 摄像头画面加**四角取景框**（8 层渐变拼的角标）+ 一条缓慢上移的**扫描线**
- 悬浮球状态点、悬浮窗绿点：识别中会**缓慢呼吸**
- 页面内面板从白底改成同一套深色玻璃；Toast 改成深色卡片 + 左侧 3px 强调色竖条
- 悬浮窗的**手部关键点骨架**从死写的荧光绿改成读主题令牌（蓝线 + 白色关节点 + 微光）

## 5. 界面预览与"眼睛验收"

`node tests/build-ui-preview.mjs` → `assets/20261004_界面改版预览_v1.html`

单个自包含文件，双击就能看六个界面（弹窗 / 悬浮窗 / 悬浮球 / 页面内面板 / Toast / 授权页）。
样式和结构全部从真实文件里抠出来内联，**每个界面塞进自己的 Shadow DOM**（否则 popup.css 和
float.css 的同名类会互相打架，预览就不准），所以改了样式重新跑一次就同步，不会出现"预览骗人"。

生成器里对 CSS 做了两处改写：元素选择器 `body` → `:host`（Shadow DOM 里没有 body）；
面板 / Toast 的 `position:fixed` → `absolute`（否则会跑出画框）。这些都是**预览专用**的改写。

第三个参数可以强制主题（`dark` / `light`），只为截图核对用 —— 无头浏览器默认是浅色。

### 5.1 用无头 Chrome 截图，真的看了一遍

静态测试查不出"样式塌了"，所以跑了一遍真渲染（Chrome `--headless=new --screenshot`，
沙箱里起不来 Chrome，需要完整权限；截图存在 `assets/20261004_界面改版预览_深色.png` / `_浅色.png`）。

**看出来的三个问题（都已修）：**

1. **页面内面板的占位文字被挤成竖排。** `<video>` 是 `width/height:100%` 的弹性子项，把同级的
   占位层压成了一条缝。改成绝对定位覆盖（和弹窗里 `.camera-placeholder` 同一套做法）。
   注意这是**旧代码就有的问题**，只是以前没人放大看过。
2. **预览里的面板压根没生效。** 真实代码里 `root` 自己就是 `.gvc-panel`，预览只搬了 innerHTML，
   少了那层壳 → 面板样式全部落空，而且补状态的脚本静默抛错、预览还是"看起来很对"。
   两个改动：预览补上外层容器；并且**补状态失败时把错误画在画框里**（红字角标），
   以后不会再出现"预览静静地显示成默认状态"这种骗人的情况。
3. **浅色主题层次发平。** 卡片和页面底都是纯白，全靠 1px 描边区分。改成
   `bg #F1F4F9 → bg-soft #F7F9FC → surface #FFF → surface-hi #EEF2F8`，
   和深色「越往上越亮」是同一套逻辑；顺带补上浅色缺失的 `--gvc-stage-text`
   （缺了它，浅色下摄像头区域的占位文字会变成深色→深底上看不清）。

还清掉了两个定义了没人用的死令牌（`--gvc-stage-line`、`--gvc-shadow`），
并加了一条反向自测：**theme.css 里的令牌必须都有人用**（免得越堆越多没人管的色值）。

## 6. 环境备注（下次别再踩）

这台机器上，**沙箱里的命令行进程（node / pwsh）**对以下目录不可写：
`memory/`、`drafts/`、`docs/`、`icons/`、`vendor/`；
可写的是：工作区根目录、`tests/`、`trash/`、`content/`、`dist/`、`assets/`（新建的）。
（我用的写文件工具走的是另一条通道，`memory/` 也能写 —— 所以本文件能写下来。）

影响：**脚本要生成的文件不能放到那些目录**，否则脚本自己跑不起来（`EPERM`）。
这次的界面预览就是因为这个才从 `drafts/` 挪到了 `assets/`。

原因：工作区根目录上有一条沙箱授权项（`S-1-4-*`，可继承），部分子目录没继承到也没被补上。
2026-10-04 跑过一次 `diagnose-windows-sandbox-acl`（结果：给 `drafts` 补了当前用户的完全控制，
验证通过），但 `drafts` 依旧写不进去 —— 卡的不在 DACL 这一层。

备份与回退命令在 `memory/acl-recovery/`（脚本会打印 `ROLLBACK` 那一行，随时可回退那次权限改动）。

**下次脚本产物被拒时，直接换到 `assets/` 或 `content/`，不要反复折腾权限。**

## 7. 追加需求：手动切换深浅色（同一天）

用户要"一个自己能切换深浅色的按钮"。做法：

### 7.1 主题怎么决定（两层）

- **第一层：跟随系统** —— 原来的 `@media (prefers-color-scheme: light)`，纯 CSS。
  保留它的理由：JS 还没跑起来的那一瞬间不会闪错颜色（扩展页面的 CSP 不允许内联脚本，
  没法在 `<head>` 里同步读存储）。
- **第二层：用户手动指定** —— `theme-mode.js` 把 `data-gvc-theme="dark|light"` 写在元素上，
  `theme.css` 的属性选择器直接盖掉系统偏好。选择记在 `chrome.storage.local.themeMode`，
  三个界面通过 `storage.onChanged` 实时同步（在弹窗里点了，页面内的面板立刻跟着变）。

代价：**浅色的值在 theme.css 里出现两遍**（媒体查询一份、属性选择器一份，约 28 行）。
为了不让它腐烂，静态体检第 11 组会**逐条比对两处**，改一边忘一边直接报红。

### 7.2 为什么属性写在宿主元素上

页面内面板长在别人的网页里，它的颜色是从页面 `:root` 继承进 Shadow DOM 的。
`data-gvc-theme` 写在**面板 / 浮层自己的宿主元素**上，元素自己的声明会盖过继承来的值 ——
于是面板能单独换主题，而且**完全不碰网站自己的 DOM**（连 `<html>` 都不动）。
content.js 里对应 `ThemeMode.init({ root: false })` + `track(宿主)`。

### 7.3 按钮的三态循环（这里踩过一次坑）

第一版按"点一下就一定换外观"写：每次挑第一个"外观不同"的候选状态。
自测立刻抓出来了 —— **「跟随系统」永远回不去**，因为 auto 的外观总和系统一致，
在深/浅两态之间无限循环。

改成固定三态循环、顺序随系统换向：`跟随系统 → 与系统相反 → 与系统相同 → 回到跟随系统`。
- 从默认状态点第一下**外观一定变**（不然用户以为按钮坏了）；
- 连点三下必定回到「跟随系统」，功能不会丢；
- 三格里必然有一格"回到跟随系统"看不出颜色变化 —— 这是三态循环的固有性质，不是 bug，
  自测里也把这条写成了断言（那一格必须是 `→ auto`）。

按钮图标自己画：`◐ 跟随系统 / ☾ 深色 / ☀ 浅色`，提示文字写明"当前是什么、点一下变什么"。
三处界面都挂了统一的 `data-theme-toggle` 标记（预览页和自测靠它找按钮）。

### 7.4 顺手做的

- `ui-icons.js` 加 `sun / moon / autoTheme` 三个图标。
- 预览页也接上了同一套 `ThemeMode`：页面顶部多了一条「跟随系统 / 深色 / 浅色」切换条，
  界面标题栏上那个小图标也能点 —— 于是预览页同时成了**手动覆盖这套 CSS 的验证工具**
  （截图核对就是靠 `<html data-gvc-theme="dark">` 在浅色偏好的无头浏览器里渲染出整套深色的）。
- 看到一处遗漏：弹窗和悬浮窗的主题按钮一开始忘了挂 `data-theme-toggle`，
  截图里那两个按钮是空的。已补，并加了自测盯着这个属性。

## 9. 试过又回退：弹窗主体的圆角（同一天，最终没保留）

需求："插件主体的边角造型是直角，改成较小的圆角。" 试了两版，最后用户要求回退，代码回到
第 8 节那个状态（提交 `65cf4b7`）。结论值得留档，免得以后重复踩：

### 9.1 弹窗的窗口轮廓改不了（硬限制）

Chrome 开发者的回复：**弹窗内容基本上就是窗口里的 iframe，宿主窗口不是扩展能控制的**
（[SO #56395186](https://stackoverflow.com/questions/56395186)）。
所以**别指望把弹窗的外轮廓变圆**，只能让主体自己有圆角、圆角外面露一圈衬底色 ——
而窗口最外面那圈永远是浏览器画的直角。

### 9.2 圆角能不能被看见，全看衬底色

第一版：衬底用 `--gvc-bg-soft`(#0E1218)，主体 `--gvc-bg`(#0A0D12)，只差约 **1.5%** →
用户反馈"还是直角啊，没变化"。
第二版：新增专用令牌 `--gvc-frame`（深 #161E29 / 浅 #DCE3ED）把差值拉开 + 圆角 8px → 12px，
才真的看得见（窗口是方的，圆角太小时四个角只剩几个像素衬底，看着像脏点）。

**验证方法的教训**：第一版我"验证"的方式是把截图**放大 7 倍**、确认圆角存在就收工了。
验证要看的是**真实观感**，不是"放大后能找到" —— 这是我这次真正的错。

### 9.3 顺手暴露的一个真 bug（已修，保留）

回退用 `git reset --hard` 会让 git 把工作区文件按 `core.autocrlf` 重新检出成 **CRLF**，
而仓库里存的是 LF —— 静态体检里带 `\n` 的正则（取 theme.css 的深色块那段）于是匹配不上，
**在 Windows 上克隆下来跑测试必红**（5 条失败）。修法：`tests/integration-check.mjs` 的
`read()` 统一把 `\r\n` 转成 `\n` 再比对。
