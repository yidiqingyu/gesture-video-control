# B 站首页「数字 1」被当成「上一集」+ 观看类手势闸门

- 日期：2026-10-03
- 版本：插件 1.2.0 → 1.3.0
- 用户反馈：在 B 站首页想选第一个视频，插件老是识别成「上一集」；
  并且希望「没打开视频的时候，不要识别上一集、提高音量这些只有看视频才用得上的功能」

## 一、根因：引擎里的「是不是 B 站首页」标志根本没同步上

离屏引擎里有个 `state.isBiliHome`，决定「B 站首页数字手势选视频」这条路走不走：

```js
if (num) {
  if (state.isBiliHome) { …triggerAction('num_' + num); return; }   // 首页：选第 N 个视频
  …                                                                 // 非首页：掉到普通逻辑
}
```

而它只有三个来源，全都有洞：

| 来源 | 问题 |
| --- | --- |
| `PAGE_INFO_SET`（content.js 上报） | content.js 里是 `if (isHome !== lastReportedHome)` —— **只在变化时推一次**。引擎后启动（或重启）时，这个"变化"早就发生过了 |
| `OFFSCREEN_START` | **弹窗发的这条消息根本没有 isBiliHome 字段**（只有面板/自检重启那条带） |
| `TARGET_CHANGED` | 只切标签时发 |

结果：打开弹窗开启手势控制后，引擎里的 `isBiliHome` 一直是初始值 `false`。
于是在首页比「数字 1」（食指向上）→ 没走数字选视频，直接掉进「食指向上 = 上一集」的分支 → 用户看到的就是"被识别成上一集"。

**修复**：不再依赖"变化时才通知"。`content.js` 的 `GET_STATUS` 响应里带上 `isBiliHome`，
引擎**每次刷新页面视频状态时一起同步**（启动时、切标签页时、之后每 3 秒一次）。

## 二、用户要求的功能：动作闸门

"没在看视频时，音量 / 上一集 / 点赞这些手势不该乱执行" —— 新增 `action-policy.js`，
把动作分成三类，纯逻辑、离线可测：

| 类型 | 包含 | 执行条件 |
| --- | --- | --- |
| **观看类** | 播放暂停(OK) / 音量增减 / 上一集 / 下一集 / 点赞 / 一键三连 | 页面上**正在放视频**（`usable`） |
| **信息流类** | 短视频模式的 ↑↓ 滑动 | 页面上**至少有视频元素**（`hasVideo`） |
| **页面类** | B 站首页数字选视频 1~6 / 🤟 换一换 / 666 锁定 / 双手食指交叉 | 随时可用 |

几个关键设计：

- **"正在放视频"怎么判断**：`content.js` 新增 `isUsableVideo(video)` —— 有时长、或播过（currentTime>0）、
  或正在播、或尺寸够大（≥320×180）才算"真的在看"。这样 B 站首页那种**卡片预览小视频**
  （没有时长、没在播、尺寸小）不会让闸门误判成"正在看视频"。
- **探测不到就放行**（`videoUsable === null`）：页面脚本没响应 / 刚启动时不能因为"没探测到"
  就把整个扩展变成不响应 —— 失败方向选"照旧执行"，而不是"全都别动"。
- **闸门放在 `triggerAction` 内部**：所有动作都从这里出去，任何分支忘了判断也漏不掉
  （`tests/integration-check.mjs` 里有一条检查专门验证这件事）。
- **提示要"粘住"**：引擎每帧都会用手势刷新状态文字，提示只设一次的话 33ms 后就被人手指数覆盖了，
  用户根本看不见。所以加了 `setHint()`：被拦下时提示粘 2.5 秒，界面显示
  「当前页面没有正在播放的视频，这个手势不执行」——不再让人猜"为什么没反应"。

顺带优化：状态刷新从"只在动作后刷新"改成**每 3 秒一次**（闸门需要它保持新鲜），
但**只在文字真的变了才广播**，避免每 3 秒往后台灌一条消息。

## 五、建议实机验证（这三条只有你那边能确认）

1. **在 B 站首页比「1」**：应该打开「换一换」旁边的第 1 个视频，而不是提示上一集（这次的主要修复）；
2. **在首页比小拇指 / 比 OK**：应该看到「当前页面没有正在播放的视频，这个手势不执行」，页面不再乱动；
3. **打开视频后再比小拇指**：音量正常增减（闸门不该误伤正常使用）。

如果第 3 条不灵（打开视频后手势被挡住），说明 `isUsableVideo` 的判断对你的播放器太严，
把 `content.js` 里 `isUsableVideo()` 的尺寸阈值（现在是 320×180）调小即可。
