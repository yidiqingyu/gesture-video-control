# 手势识别「用一段时间就不响应」修复（自检 + 自动恢复）

- 日期：2026-10-03
- 版本：插件 1.1.0 → 1.2.0
- 起因：用户反馈「用一段时间它就不再对手势进行操作了，需要点一下插件才重新识别」

## 一、结论（根因）

用户在诊断里提供的两条现象直接把问题定死了：

> 「打开弹窗就没问题，隐藏弹窗过段时间就不回应」
> 「每次用手势关闭当前页面后它也不再响应，需要再点插件呼出弹窗」

这两条分别对应两个**结构性缺口**（不是识别算法的问题，算法那轮已经修过了）：

### 缺口 1：整个扩展没有「断了会自动回来」的机制
- MV3 的后台 Service Worker **空闲约 30 秒就被浏览器回收**；离屏识别页也可能被关掉，
  或者因为它是「不可见页面」而被浏览器的**冻结 / 定时器降频**策略降速甚至冻住。
- 全项目搜不到 `chrome.alarms`，也没有任何地方会检查、重建离屏识别页：
  `ensureOffscreen()` 写了 4 份（background / popup / float / grant），但**只在用户点弹窗、
  点面板、开授权页时才会被调用**。
- 为什么「开着弹窗就正常」：弹窗里有 `setInterval(refreshFromBackground, 2500)`，
  每 2.5 秒发一次状态查询 —— 正好**替用户把 Service Worker 一直喂着**。
  弹窗一关，这条心跳消失，30 秒后后台被回收，而**没有任何代码把它救回来**。

### 缺口 2：用手势关掉当前页面后，控制目标失效
- 「双手食指交叉」这个手势走 `CLOSE_TAB` → `chrome.tabs.remove(tabId)`，把**正在被控制的标签页**关掉了。
- 之后 `state.targetTabId` 还指着那个已经不存在的标签页，所有手势指令都发给一个死页面。
- 旧版只在 `bilibili.com` 的标签激活/加载时才会重新指向目标，而且**没有任何
  `chrome.tabs.onRemoved` 处理**，所以关掉页面后就是"永久失灵"，只能点插件重新指向。

### 另外两个隐患（同类问题）
- 浏览器重启后不会自动恢复（没有 `chrome.runtime.onStartup`），storage 里开关还是 ON，
  但引擎根本没启动。
- 摄像头被其它程序抢占 / 画面卡住时没有任何监听（`track.onended`、画面 `currentTime` 不前进），
  画面定格后识别永远停在最后一帧。

## 二、改了什么

### 新增 `health.js`（自检决策，纯函数可离线测）
把「探测结果 → 该做什么补救」做成一张判定表：重建离屏页 / 重启引擎 / 重新指向标签页 /
补注入页面脚本 / 什么都不做，并区分几种要告诉用户的状态（正常、正在恢复、需要点图标、
浏览器重启需开一次弹窗、反复失败要查摄像头）。

### `background.js`（自检执行者）
- 加 `alarms` 权限，**每分钟自检一次**（只在手势控制开着时存在，关掉开关就清掉闹钟）：
  1) 离屏识别页还在吗、有响应吗；2) **帧数还在涨吗**（不涨 = 卡死或被冻结，连续两轮就重建）；
  3) 控制目标标签页还在吗；4) 页面脚本还响应吗。
- 发现异常自动执行：关掉并重建离屏文档（`closeDocument` 由 Service Worker 执行，
  不依赖那个可能已经被冻结的页面配合）→ 用持久化的设置重新启动 → 在页面上提示「已自动恢复」。
- 恢复后**要等几秒再探一次**确认真的起来了，才在页面上报喜；连续 3 次救不回来就停止折腾，
  把状态标成"请检查摄像头"，避免每分钟空转。
- 新增 `chrome.tabs.onRemoved`：控制目标被关掉（就是用那个手势关的）→ 立刻指向当前活动标签页。
- 标签跟随从「只有 B 站」扩展为「所有固定权限的视频站」。
- `TAB_MESSAGE` 转发失败时，先尝试补注入一次页面脚本再重试一次。

### `offscreen.js`（引擎自愈）
- **持有一把 Web Lock**：浏览器对不可见页面的定时器会节流甚至冻结，而本引擎正是
  `setTimeout` 驱动的；持有 Web Lock 是浏览器认可的"我还在干活"信号，从源头降低被降频的概率。
- **摄像头看门狗**：监听 `track.onended`（被抢占/拔掉）+ 检查画面 `currentTime` 是否还在前进
  （卡住 3 秒）→ 自动重启摄像头与模型。
- 新增 `OFFSCREEN_RESTART` 兜底指令；状态里补上 `cameraAlive` / `lastFrameAt` 供自检判断。
- `TARGET_CHANGED` 支持 `tabId: null`（暂时没有控制目标）。

### `content.js` / `popup.js`
- 新增 `SHOW_TOAST` 消息：自动恢复后在页面上说一声，不让用户以为它偷偷死了。
- 弹窗新增自检状态行：正在恢复 / 需要点一下图标 / 浏览器重启需开一次弹窗 / 反复失败查摄像头。

### `manifest.json`
- 加 `alarms` 权限（不弹安装提示）。
- 按用户选择，给常用视频站加固定权限（B 站 / YouTube / 抖音 / 腾讯视频 / 爱奇艺 /
  优酷 / 西瓜 / 芒果），**仍然不申请 `<all_urls>` 全站权限**；这些站的页面跳转、刷新后
  控制能自动接回（Chrome 规定：点图标给的临时授权在页面刷新后就作废，这是唯一的解法）。

### 设计取舍（明确记录）
- **浏览器重启后不自动开摄像头**：用 `chrome.storage.session` 区分「同一次浏览会话中途断了」
  和「刚开机」。后者只提示"打开一次弹窗恢复识别"，避免"Chrome 一启动摄像头就自己亮了"的观感。
- 任意网站（不在固定权限清单里）被刷新后，Chrome 不允许自动补脚本，只能提示用户点一下图标——
  这是平台限制，不是 bug；弹窗里会明确写出来。

## 六、遗留 / 注意

1. **权限变化需要重新确认**：新加了固定站点权限，Chrome 在更新未打包扩展时可能提示重新授权，
   在 `chrome://extensions` 点一下「重新加载」即可。
2. 自检闹钟的周期是 1 分钟（Chrome 对正式扩展的最小周期），也就是说最坏情况下
   断了约 1 分钟内会被自动修好；期间页面不会有反应，这是可接受的代价。
3. 建议实机验证一遍这三条：① 关掉弹窗看视频 10 分钟以上，手势是否一直有效；
   ② 用手势关掉当前页面后，换一个视频页手势是否还灵；③ 把摄像头拔掉/被占用，
   弹窗是否给出明确提示。
